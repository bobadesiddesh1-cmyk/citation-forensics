# AnswerShare — Decision Log

Product-A pivot decisions. Engine-level decisions (matching thresholds,
extraction, byte-exact restore, `<all_urls>` sentinel design) are inherited
from CiteTrace — see `../citetrace/DECISIONS.md` #1–#15.

1. **Own-site setup, not agency workspaces (v1).** Settings hold one set of
   "my domains" + competitors + topics. Chosen because it ships now and
   collects data immediately; a client-workspace layer can wrap the same
   record schema later (records are workspace-agnostic).

2. **Engine files are copied, not referenced.** Chrome loads an unpacked
   extension from one folder, so `tokenizer/matcher/citability/extract/
   highlighter` are byte-identical copies of the CiteTrace files. They keep
   the `globalThis.CiteTrace` namespace so the pure modules stay mutually
   compatible and unit-testable with the same harness.

3. **Passive capture stores the answer text** (trimmed to 15,000 chars per
   record). Without it, "ANALYZE WHY →" from the dashboard would be
   impossible later. It's the user's own chat content, stored only locally,
   capped at 2,000 records FIFO, clearable in one click.

4. **Dedup by signature** `site|query|sorted-citation-domains`: MutationObserver
   re-scans would otherwise log the same settled answer repeatedly. A
   genuinely re-asked query that returns different citations logs again by
   design (that's a new data point).

5. **Rank = citation order in the DOM** after redirect-unwrapping and
   dedup — a proxy for prominence, not a claim about the engine's internal
   ranking. Documented in the dashboard column header ("citations (ranked)").

6. **No competitor list → every non-you citation counts as competition.**
   Losses are then simply "queries where you weren't cited", which is the
   correct default reading for a fresh install.

7. **Share of voice = % of records where the domain appears at least once**
   (not citation-count share) — matches how SEO rank trackers report
   "visibility" and is robust to engines that cite the same domain 5×.

8. **Winner profiles are saved automatically** after any successful trace
   with ≥1 cited passage; profiling your own page is explicit (URL →
   profile job). Auto-saving "mine" profiles on every page visit would
   require running extraction on ordinary browsing — rejected on privacy
   grounds and on the sentinel's do-nothing guarantee.

9. **Winner vs mine profiles measure different populations** (cited
   passages vs all sentences) — deliberately: "what the AI picked from
   their page" vs "what your page offers". The compare view labels both
   sides accordingly and the fix templates account for it.

10. **Trend buckets are fixed 7-day windows ending now** (8 weeks), computed
    from all records regardless of the range filter — a trend with the
    filter applied to both axis and window would show a flat line for
    "last 7 days".

11. **`#answershare=` fragment** (not `#citetrace=`) so both extensions can
    be installed side by side without claiming each other's trace jobs.
    Message types and storage keys are likewise `ANSWERSHARE_*` /
    `answershare_*`.

12. **Loss list caps at 50 rows, records view at 200 rows** rendered —
    keeps the DOM snappy at the 2,000-record cap; CSV export always
    contains everything.

13. **Toasts are report-outcome only and can be disabled** in settings
    (captureToasts). The "your domain NOT cited" toast is the product's
    core emotional loop, so it defaults on.

14. **Icons**: radar motif (rings + sweep + red blip) generated by a pure-
    Python PNG writer — same no-binary-assets policy as CiteTrace, visually
    distinct so the two toolbars icons never get confused.
